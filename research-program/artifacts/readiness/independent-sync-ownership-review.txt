### 2. Fix is load-bearing in **both** changed modules — contract alone would not stop active-PR closure

`sync_pr_merge_contract.js` now sets `foreignPlan`, clears `stale`, and returns early eligibility:

```777:787:.github/scripts/sync_pr_merge_contract.js
  const foreignPlan = Boolean(planId && record && record.plan_id !== planId);
  if (foreignPlan) {
    return { ...selection, stale: [], deliveryRecord: record, foreignPlan,
      eligibility: { eligible: false, reason: 'plan_mismatch' } };
  }
  if (planId) {
    selection.stale = selection.stale.filter(
      (pr) => parseDeliveryRecord(pr.body || '')?.plan_id === planId,
    );
  }
```

`stale: []` only prevents **other** PRs from being closed. Without the Maint 71 guard, the active foreign-plan PR would still hit the superseded-close path above (`deliveryRecord` present, `reason === 'plan_mismatch'`).

The new early exit is required:


### 5. Minor behavioral side effect — plan-bound stale cleanup skips record-less PRs

When `planId` is set, stale cleanup only includes PRs whose parsed delivery record’s `plan_id` exactly equals `planId` (`:785-787`). Same-lane PRs **without** a delivery record (`parseDeliveryRecord(...) === null`) are no longer closed as stale during plan-bound runs. Pre-fix they would have been.

**Confidence: medium-low** this matters in production; only flagging because it is a real logic change, not covered by tests.

### 6. Out of scope for this fix — unscoped Maint 71 still has no plan ownership guard

When `expectedPlanId` is empty, `foreignPlan` is always false (`:779`) and the stale filter is skipped (`:784`). Scheduled/unscoped janitor runs (`maint-71-merge-sync-prs.yml:27-33`, run-name `'unscoped'`) are unaffected. That is separate from plan-bound campaign retries, which always require `expectedPlanId` for `candidate`/`campaign` (`:893-899`).
