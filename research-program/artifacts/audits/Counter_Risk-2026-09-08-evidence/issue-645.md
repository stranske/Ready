**Why** The pipeline's deterministic compute/IO core is fully working and headless-capable — `run_pipeline_with_config(config, *, config_dir, output_dir, formatting_profile)` (`src/counter_risk/pipeline/run.py:261`) is a clean in-process entry that produces `manifest.json` + `DATA_QUALITY_SUMMARY.txt` (`src/counter_risk/pipeline/manifest.py:21,139`) and emits only **relative** output paths (asserted in `tests/pipeline/test_run_pipeline.py::test_run_pipeline_writes_expected_outputs_and_manifest`, the `not Path(output_path).is_absolute()` loop ~line 1834). But a non-developer evaluator on a locked-down work PC (no installs, no terminal, browser only) or a home Mac has **no** way to try it: there is no web app (no Streamlit/Flask/FastAPI/Gradio in `requirements.txt`, `pyproject.toml`, or code), no `.devcontainer`, no hosted demo, and no CI artifact that surfaces a run folder — the only `upload-artifact` steps are agent/metrics/release (`.github/workflows/release.yml`, `agents-weekly-metrics.yml`, etc.), and `release.yml` builds a Windows-only PyInstaller `.exe` only on release. The README itself frames the operator path as an Excel/Windows-app Runner (`README.md:7`), not a browser.

**Privacy constraint (binding on this issue):** the org cannot send proprietary counterparty data to external/community SaaS (no Streamlit Community Cloud, no public Hugging Face Space with real data) and cannot send proprietary data to external LLMs without authorization. It has no objection to deterministic programs processing real data. Therefore the browser demo MUST be one of: (a) **client-side WebAssembly** (stlite/Pyodide/JupyterLite) running entirely in the evaluator's browser with zero data egress; (b) **internal browser-accessible hosting** inside the org perimeter (internal web app / Posit Connect / Streamlit-in-Snowflake / internal Azure app); or (c) an **external demo using only the bundled synthetic fixtures** in `tests/fixtures/`. In every case the LLM chat surface (`src/counter_risk/chat/`) must be DISABLED or gated behind an authorized no-train endpoint — the demo must never call an external LLM with uploaded data.

**Scope** Deliver the lowest-effort viable browser path that meets the constraint, plus a smoke test. Recommended: (1) a `workflow_dispatch` CI job that runs the fixture pipeline and uploads the run folder as a viewable artifact (synthetic-fixture-only, zero real data), AND (2) a thin stlite/Pyodide single-page app committed under `web/` that loads the bundled fixtures and renders the data-quality summary + manifest entirely client-side, with the chat feature compiled out. Pick at least the CI artifact path as the floor; the stlite page is the higher-value add.

**Non-Goals**
- Do NOT deploy any app or CI demo that ingests, uploads, or transmits real/proprietary counterparty data to an external service — fixtures only for any externally reachable surface.
- Do NOT wire the LangChain chat assistant (`src/counter_risk/chat/session.py`, `chat/providers/langchain_runtime.py`) into the public/browser demo; it must be disabled or stubbed (the offline stub gate `COUNTER_RISK_CHAT_OFFLINE_MODE=1` exists for exactly this).
- Do NOT add browser-path documentation to the README `## Testing` section — `tests/test_readme_testing_section.py` asserts that section is exactly one autopilot-smoke sentence of 10-20 words and will fail; document the demo in `WORKFLOW_USER_GUIDE.md` or a new `docs/browser_demo.md` instead.
- A committed scaffold (empty `web/` dir, a workflow that does not actually upload a run folder) does NOT close this; the artifact must be downloadable/openable and the smoke test must run the fixture pipeline.

**Implementation Notes** Programmatic entry: `run_pipeline_with_config(...)` at `run.py:261`; it serializes the config to a temp YAML and calls `run_pipeline`, returning the run dir. COM-only steps already self-skip off-Windows — `_refresh_ppt_links` returns `SKIPPED` on `platform.system() != "windows"` (`run.py` ~2887), and `pdf_export` skips when COM is unavailable (`outputs/pdf_export.py:55-67`) — so a Linux CI runner or a Pyodide/WASM host produces the historical workbooks, a screenshot-replaced/copied PPTX, and the manifest, just without link-refresh/PDF. For stlite, pandas + openpyxl + python-pptx are available as pure-Python/wasm wheels; `Pillow` PNG rendering and any C-only paths may need the pure-Python ZIP media-swap backend (`ppt/replace_screenshots.py`) rather than COM. Bundled fixtures live in `tests/fixtures/` and are already self-contained (the release spec even bundles the PPTX as a template, `release.spec:20-22`).
